# 御魂社区御魂配置

Cloudflare Workers 提供 JSON 接口，D1 存储六件御魂的结构化属性。无需 R2、图片上传或 AI 服务。用户在桌面端点击上传后，所选**实际方案**不论评分多少都可上传，无需设置或满足目标评分范围；未来条件推算不能直接上传。

已部署地址：[御魂社区服务](https://onmyoji-soul-community.liukele015.workers.dev)。应用已默认连接该地址，无需用户自行填写；「社区连接与上传」仍支持切换其他自建服务。数据库 ID 和账号 ID 是部署资源标识，配置文件中没有账号密钥。后续更新在本目录运行 `npm run deploy` 即可。

## 部署

在本目录运行：

```powershell
npm install
npx wrangler login
npx wrangler d1 create onmyoji-soul-community
```

将创建结果中的数据库 ID 填入 `wrangler.jsonc` 的 `database_id`。两个限流 `namespace_id` 需在你的 Cloudflare 账号内唯一，已有同编号命名空间时改用未占用编号。

```powershell
npm run migrate:remote
npm run deploy
```

把部署返回的 `https://onmyoji-soul-community.<账号子域>.workers.dev` 地址填入桌面端「御魂配装 → 目标评分分析 → 社区御魂配置 → 社区连接与上传」，点击「保存并连接」。开发者可先写入应用布局配置键 `onmyoji-studio.souls.community` 的 `endpoint` 字段，让所有用户连接同一服务；不要把 Cloudflare API Token 放入客户端。

本地验证使用 `npm run migrate:local`、`npm run dev`，桌面端服务地址填 `http://127.0.0.1:8787`。应用使用主进程网络接口，不需要开放浏览器跨域访问。

## 行为

- `GET /v1/builds?heroId=...&objective=...&cursor=...`：按式神、指标分页读取，最多 50 个方案。支持 `search`（名称或署名包含文本）、`author`（署名包含文本）、`suit4` / `suit2`（实际至少四件 / 两件，选相同套装时需要六件）、`main2` / `main4` / `main6`（主属性内部名称）、`after` / `before`（`YYYY-MM-DD`，北京时间，包含开始与结束当天）、`order=newest|oldest`。多个条件取交集，在全库筛选后按创建时间与 ID 稳定分页，文本按字面匹配，`%` 和 `_` 不作为通配符。响应的 `filterVersion: 1` 表示支持全库筛选；`cursor` 用于同一组条件与排序的下一批，改变条件后须清空游标。数据库迁移 `0003_filter_indexes.sql` 为已有方案的二四六号位主属性建立索引；上线时先运行 `npm run migrate:remote`，再运行 `npm run deploy`。
- `POST /v1/builds`：JSON 方案，`X-Delete-Token` 为客户端本地生成的 64 位十六进制管理凭据。服务端重建允许字段，校验六个位置、六星 +15、属性范围、目录中的式神基础面板与套装，不限制方案评分，也不以满足面板范围作为上传条件。真实御魂允许主副属性同名，副属性列表自身不允许重复。体积上限 24 KB。同一上传者的相同内容重复提交不增加条目。
- 方案名称由客户端与云端根据式神名、六件御魂的实际套装及件数生成，不接受用户自定义名称。署名与管理凭据在本机立即保存，重启后恢复；留空时自动生成署名。D1 的 `community_authors` 唯一索引按规范化后的署名检查重名，其他上传者使用已占用署名会收到 409；相同管理凭据可继续使用或修改自己的署名，公共列表同步显示新署名。撤回配置后仍保留署名归属。
- `DELETE /v1/builds/:id`：`Authorization: Bearer <撤回凭据>`。凭据仅以 SHA-256 摘要存储于服务端，不出现在公共列表中。桌面端保留上传 ID，提供「撤回上传」。清除本地应用配置会丢失撤回凭据，之后需由服务管理员删除。
- 只上传选中的六件御魂、式神 ID、基础面板、评分指标、属性限制及可选的参考目标范围、署名和自动方案名称；不上传账号、实例名、背包其他御魂、原始物品 ID、本地路径、图片地址。
- 社区比较以**查看者当前基础面板、指标及限制**重算，不信任上传者声称的评分。符合当前条件及目标的配置优先，随后按评分差距排序；不符合套装、两件套属性、主属性、面板范围的配置标出原因。逐位置比较副属性、主属性与固有属性。当前加载的样本不能代表全体玩家分布。
- 桌面端还支持当前条件（符合、达标、优于原方案、不符合）、当前评分及差值范围、八项面板上下限，百分比输入使用显示的百分数（如暴击填 `100`）。这些条件和推荐、评分、接近程度排序以本机重算后的**已加载结果**为范围，界面明确显示已加载数、匹配数和未加载提示；继续加载会扩大该范围。每页 12 / 24 / 48 条，仅渲染当前页卡片。署名、套装、主属性、日期和搜索修改后点击「应用筛选」，当前条件、评分和面板范围即时生效。筛选条件按式神和指标保存在本机，支持重置全部、本机收藏及「我的上传」，收藏不会同步到其他设备。连接尚未更新的旧服务时自动回退到本地筛选并提示范围。
- 分享数据为用户自报配置，未证明真实游戏持有或套装完整技能收益。匿名署名并非已认证账号。数据量和参与者增长后，可扩展账号、审核及举报；本版按 IP 在各 Cloudflare 位置限流，读取每分钟 60 次、写入每分钟 5 次，不构成全局严格配额。管理员可直接在 D1 删除违规条目。
- 服务端与客户端共用评分和校验代码，目录或评分模型更新后应同步重新部署 Worker。

部署依据：[D1 Worker API](https://developers.cloudflare.com/d1/worker-api/)、[D1 数据迁移](https://developers.cloudflare.com/d1/reference/migrations/)、[Workers 限流绑定](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/)。
