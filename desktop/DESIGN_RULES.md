# AutoFlow Studio 桌面端设计规则

## 核心规则：禁止卡片亮边

- 卡片、节点、模块窗口和弹窗不得使用高亮描边、霓虹描边或发光阴影表达层级。
- 选中状态优先使用低明度背景变化、标题带变化或一条克制的状态标记；边线只能是低对比度细线。
- 模块之间依靠背景明度、间距和暗色分隔线区分，不把页面区域包装成悬浮卡片。
- 阴影只用于菜单、弹窗和浮动窗口与底层内容的空间分离，并且只能使用中性暗色阴影。
- 控件默认保持平面化。悬停使用背景变化，不通过亮边框制造反馈。

## 强调色使用范围

- 运行、失败、成功等有明确语义的状态点和连线可以使用状态色，但不得附带发光滤镜。
- 键盘焦点可以使用清晰的一像素焦点提示，以保证可访问性；不得扩散成光晕。
- 模块拖动时的停靠落点可以临时使用强调色，拖动结束后必须消失。
- 主命令可以使用实色背景，但同一界面只保留一个主要视觉命令。

## 画布卡片：UE 蓝图样式

画布上的节点卡片、变量卡与实例卡统一采用 Unreal 蓝图编辑器的视觉语言。这条规则是对
「禁止卡片亮边」的**明确例外与边界**：允许用实色标题带表达分类，不允许发光。

- **标题带**：卡片顶部整条色带按分类着色（`--card-tint` 主导，混入当前主题的表面色，
  于是深色/浅色/石墨/暖色/对比主题都自动跟随）。色带上沿可以有一条浅色内描边把它和卡身分开；
  卡身保持中性表面色，一屏几十张卡不会各自整块跳色。
- **分类只改 `--card-tint`**：卡面底色、标题带底色一律由 `.studio-card` 统一派生，
  分类规则不得直接声明 `--card-bg` / `--card-head`。
- **端点形状**：执行流端点是**朝下的箭头**（画布执行流自上而下），数据端点是**粗圆环，右缘接朝右的小三角**。
  数据端点只有两态，输入口与输出口共用：**未连接时中间中空，连接后整颗填满**（都用同一个数据身份色）。
  「已配置」也算连接——一个参数只要有值（字面量、变量或引用）就填满；只有连默认值都没落的参数留空环。
  输出口的判据是「有没有人连它」：任务卡看输出是否被引用，变量卡看这个变量有没有人在用。
  端点的几何与命中载体仍是原来的 `<circle class="port …">`，小三角是紧跟其后的 `<path class="port-glyph">`，
  因此端点位置公式、命中范围与缩放分级都不受影响。
- **值卡片没有执行流端点**：布尔判断（`bool_judge`）与拆分（`break`）只带数据端点，
  卡片顶边不画执行入口箭头——它们不产出执行流，值由别的节点引用 `nodes.<id>.output...` 取用，
  一条悬空的入口箭头只会让人去找那条并不存在的父连线。父节点的执行线仍可从输出口拖到卡片顶边接上
  （命中测试按几何算），落点就在卡片顶边，只是不再画入口箭头。
  例外仅限这两类值卡片：Task、组合节点与判断节点的入口箭头始终保留。
- **值卡片的卡面按表达式形态排**：布尔判断卡只有 `{op: [a, b]}` 这种二元比较才画 UE 紧凑节点的
  两个操作数格；`{ref: ...}`（整卡绑一个 bool 来源）只留一个布尔口；`and/or/not/exists`
  只回读整句中文，编辑走「嵌套条件（进阶）…」。**认不出的形状不许在卡面上编出并不存在的引脚**
  ——宁可只回读，也不能让 `{and: [0, 0]}` 看起来像 `0 and 0`（形态判定见
  `desktop/src/canvas/model/exec-ports.ts` 的 `boolJudgeShape`，卡面、引脚投影与写值路径共用它）。
- **值卡片要有自己的分类色**：布尔判断冷蓝、拆分玫瑰，与执行流卡片（灰蓝/青绿/金/紫）分开
  ——它们没有执行流端点，配色也不该像流程节点。分类色仍然只落在 `--card-tint` 上（标题带、
  色条、图标与卡面文字由它派生），卡身底色与描边不动；值卡片另带 `.studio-card.value-card`
  样式钩子。给卡片加分类时必须同时补类型色，否则会落到 `category-control` 的兜底灰蓝。
- **值卡片的标题由类型派生**：拆分的标题是 `Break <来源名>`（UE 的 `K2Node_BreakStruct` 命名成
  `Break <Struct>`），布尔判断的标题是运算符中文名（`等于` / `大于` / `并且` …，等于 UE 把比较节点
  命名为 Equal / Greater）。优先级是**手动 `name` > 类型派生 > 节点 ID**：`name` 层是本项目特有的
  覆盖能力（UE 里普通节点不能逐个改名），没设过时标题不许出现内部标识——稳定 ID 只活在卡片悬停
  提示与引用文本里。画布卡片、左侧结构树、值卡片浮层与顶栏搜索必须共用同一份标题
  （`desktop/src/canvas/model/node-title.ts`），不允许某一处自己拼名字。
- **连线**：执行流连线是粗而亮的浅色线；变量线与节点输出引用线更细、按数据身份取色，
  并在落点前收一个小箭头。线一律实线，不加发光；悬停与选中只提亮、加粗或换状态色。
- **连接反馈**：拖线时画出浅色预览线，落到兼容端点上时预览线提亮、虚线收掉，
  同时目标卡片的描边与执行流端点一起点亮。
- 缩放分级只决定「还显示什么」，箭头与圆环都必须进概览档的隐藏清单，否则会留下悬空小点。

## 配色基准

- 整体采用 Unreal Editor 风格的中性炭黑层级：系统标题栏接近黑色，工具栏和标签栏使用深灰，模块内容区使用略亮的中性灰，避免蓝灰色大面积主导界面。
- 蓝色只用于选中、焦点、停靠提示和少量编辑状态；运行、成功、警告、失败继续使用低饱和绿色、黄色和红色。
- 内容层级主要通过 `#141414`、`#202020`、`#252525`、`#2c2c2c` 与低对比度灰色分隔线表达，不使用渐变背景。

## 外观与设置

- 设置采用左侧分类、右侧内容的布局，分类为外观、界面、运行、快捷键、关于。
- 设置默认与“工作流编辑器”叠在同一行标签打开，不停靠在右侧独立分组；用户仍可手动拖出或弹出。
- 快捷键在设置中可逐条修改、恢复默认并持久化到应用配置；工作台、工作流画布与独立窗口共用同一份绑定，改动实时同步。"固定操作"（鼠标手势、Esc、菜单导航）只展示不可改。
- 打开的工作流画布（标签、激活项与未保存内容）作为会话持久化到应用配置；重启时在“启动时恢复上次画布”开启的前提下恢复，关闭该项后回退到“启动时加载默认工作流”。
- 外观提供深色与浅色，默认深色。主题保存在应用配置中，主窗口、独立窗口、画布、详情和日志同步，不依赖当前本地服务端口。
- 浅色使用柔和灰白背景、深灰文字和低饱和状态色；同样禁止亮边和发光。不对图片、截图或整个窗口应用反色滤镜。
- 浅色的画布、节点、停靠标签和表单须单独设定层级：灰色画布、纸白节点、深灰正文、蓝灰选中。不可仅使用自动颜色转换；SVG 文字不能当背景填色，全部标签状态都要指定可读文字色。
- 通用语义色维护在 `public/theme/theme.css`；旧界面的色彩适配由 `scripts/build-light-palette.cjs` 生成，不手工修改生成的文件。新增界面优先使用语义色。

## 模块窗口

- 自定义系统标题栏保持独立；标题栏下方的文档工具栏、内部停靠区和状态栏共同组成一个顶层“工作流编辑器”模块。
- “工作流编辑器”是顶层工作台的兜底根模块，必须始终存在，不允许关闭、拖动、浮动或移到独立窗口；与它合并的其他标签仍可单独拖走。
- 顶层工作区模块与内部功能模块采用嵌套停靠结构，未来可与资源管理、运行管理等同级模块叠为标签或重新停靠。
- 模块标题栏、标签栏和内容区使用连续的平面结构。
- 活动模块通过较深或较浅的标题填充区分，不使用亮色外框包围整个模块。
- 分隔条必须可拖动，但静止时保持低对比度。
- 结构、节点、变量、工作流画布、详细信息和运行日志都应能关闭、重新打开、停靠、叠成标签组或浮动。
- 内容浏览器默认是与整个工作流编辑器同级的顶层模块，并停靠在工作流编辑器底部；它既可以在外层拖到编辑器左、右、上、下或中心叠为标签，也可以跨层级拖入工作流编辑器内部，与画布、详细信息等内部模块停靠或叠为标签，并能再拖回外层。任一时刻只保留一个内容浏览器实例。目录和内容项使用平面列表或缩略图，不使用亮边卡片。
- 内容浏览器参照 UE 布局：左侧内容源目录、中间类型过滤列、右侧“显示方式 + 搜索 + 资产网格 + 条目计数”；面板变窄时依次收起过滤列与来源列，只保留主网格。类型过滤在当前目录下递归收集同类条目，因此在项目根目录也能看到深层模板图片；搜索框跨整个项目匹配，“全部”只显示当前目录的直接子项。
- 运行日志默认停靠在工作流编辑器内部底部；它与内容浏览器采用相同的跨层级停靠能力，可以拖到整个工作流编辑器左、右、上、下或中心叠为外层标签，也可以再拖回工作流编辑器内部。任一时刻只保留一个运行日志实例。
- 运行日志以结构化节点步骤为主视图，显示节点名称、语义化操作、状态、耗时、调用路径、参数、输出和运行截图；多实例运行按实例分栏，进程 stdout/stderr 只放在“引擎输出”辅助页签。停靠高度较小时优先保证当前节点标题、状态和耗时可见。
- 详细信息模块默认固定在工作流画布右侧；点击节点卡片后在该模块内编辑参数，不允许在画布内部临时展开参数卡片。
- 用户布局应自动保存，并提供“恢复默认布局”。

## 实施要求

新增或修改界面前应先检查本文件。若现有组件与这些规则冲突，应在当前改动涉及到该组件时一并修正。

- 不操控用户电脑或桌面窗口进行验证，不启动 Electron 窗口执行鼠标、键盘、拖拽或截图检查；验证仅使用类型检查、构建和不依赖界面操控的自动化测试。
- 每次修改完成后应重新启动程序，确认改动生效且运行正常后再交付。
