## 修复依据和边界

### 行动条核验的范围

补查000425、000650、001050完整帧后，目前只能确认关键调度现象吻合：首次寻香行领先；000650出现修罗鬼童丸「行动提前」；其第二次普通行动在雪女之后、季之前（001050附近）；修正市加美错误加速后，第二轮虫师、千姬在市加美之前。

这不等于右侧头像的像素位置或每个式神的行动条百分比已通过验证。录像没有数值刻度，头像存在重叠与技能期间的移动，当前施法者还单独显示；模型按调度事件推进，并不记录动画帧。因此不能把任意帧的头像纵坐标直接换算成模拟百分比，也不能从「行动提前」文字单独证明拉条量恰好40%。全场逐节点百分比仍未闭合，胜负与状态分叉之后更不能宣称行动条持续一致。

### 寻香行耗火

旧实现把明香境的旧等级描述解释成全局减耗1火，使菩提愿3火被减为2火，再叠加海月1火，首次合计只扣3火。客户端3913技能行的consumeVal为3；3912四/五级技能行自身consumeVal为2，并不能再给3913扣1火。删除明香境的全局减耗，首次3+1=4火，后续海月条件不满足时3火，与本场帧数相符。尚未据本场验证低等级明香境的所有交互。

### 市加美首次选招导致错误加速

000675帧明确显示寂灭现前。旧模型以速度状态6008作为选招代理，忽略先机已经存在的垂悯状态，先放爱见舍离并加100点速度。于是第二轮市加美插到虫师、千姬之前。

现在将已有垂悯状态也纳入选招代理，本场首次用6003，第二轮自然顺序恢复为寻香行→海坊主→虫师→千姬→市加美→御怨般若。此处属于录像支持的AI修正，仍保留partial标记：权威AI数据未闭合，尚不能从单场证明所有队友增益组合的泛化行为。

### 原生减伤属性与伤害倍率不同

客户端buff3961三级attrList为hurtReductionRate=0.3；buff3312为每层hurtReductionRate=0.05。`calcRawAttackDmg.txt` 的1904–2012指令先累加目标属性，再对非负值执行realHurt /= (1+hurtReduc)。

旧模型把它们存成damageTaken负百分比。魂网三层旧口径剩10%伤害，原生口径剩1/1.9≈52.63%；仇恨印记九层旧口径剩55%，原生口径剩1/1.45≈68.97%。两者都夸大了红方生存能力。

增加独立hurtReductionRate属性，与面板原有属性相加后交给已有原生伤害公式；修罗鬼童丸魂网、御怨般若仇恨印记改用该属性。覆盖与面板叠加、不同层数、重伤延迟减伤记录。其他式神的damageTaken并未因名称相似被批量改写，仍需逐个核对其原生属性/特殊伤害回调。

## 仍未对齐的原因

1. **随机目标和招财触发**：seed=1的谵妄落在千姬，首次千姬强制攻击友方；实机明确召戟。同组样本中多数千姬可以正常召戟，所以不能把所有红胜归因于这一点。招财也会改变雪女是否有2火、御怨是否能首次开大，进而改变后续战斗。未获取客户端随机种子，不应强行宣称逐行动重放同一条随机序列。
2. **第二轮蓝方供火仍分叉**：实机001575–001600附近从0到3，seed=1仍为0；001850附近实机寻香行能用菩提愿，seed=1随后只能普攻。需要继续区分海原贝戟计数、供火进度及流光失辉限制的实际状态，不凭HUD数字直接归因给某个被动。
3. **封印后的持续保护、控制和目标选择**：实机蓝方最后仍存活获胜，多数样本蓝方在封印后被击杀。尚未闭合每次护盾消耗、幽谷响反射控制及迷障目标链，不能把差异全部解释为随机，也不能修改胜负结算来迎合录像。
4. **同赢家不等于重放成功**：样本8（实际种子550837354）蓝胜，但其雪女第一次招财加2火，之后千姬/寻香行顺序也与录像分叉。它只说明修正后的引擎能产生蓝胜，不能证明这场完全复现。
