# 14点场胜负差异追查

实机蓝胜；此前固定10样本蓝胜1、红胜9。行动者次序相同并不代表技能、目标、鬼火和存活状态相同。本轮沿这些分支检查，并作相同输入和种子的对照干预。

## 已确认并修复：鬼面强制选招

`resentment-hannya.ts` 的 sealMask.selectAction 原先在敌方有至少1火时强制选择3316怨恨祛除，覆盖该式神原策略。消耗1火、主动破2面并放弃正常技能。

客户端技能行3316描述为“敌方可主动施放此技能”；14点场002023帧在御怨般若结界内明确显示千姬“汐梦”，蓝火4→2。因此不能把可用破阵技能实现成强制出招。

已移除状态的强制选招，保留grantedSkills、1火费用和破面结算。既有破阵回归改为显式选择该技能，新回归验证有火时正常出招、鬼面不擅自扣火、只在回合结束自动破1面。

相同10个种子修复前蓝1红9，修复后蓝2红8。旧模型这10场各有1至7次主动破阵，修复后均为0。胜负样本的变化并非每个都单调改善：样本0、6红转蓝，样本8蓝转红。修改结算也会改变后续随机调用序列，故这组对照说明模型敏感性，不能当作真实胜率或独立效应估计。

## 明确的重放差异：千姬受到谵妄

直接seed=1当前仍红胜。其首次谵妄对象是blue:4:356千姬，千姬整场三次行动均是3561普攻，没有召戟。实机000775附近明确召戟；000650左侧季上方可见红色失魂图标。这两条路径并非同一条随机轨迹。

未召戟会丢失海原贝戟供火、恢复及汐梦附加效果，所以不能用“前24个可见行动者一致”来认定战斗状态对齐。十个派生种子中只有样本5整场未召戟；其余8个仍可红胜，故不能把红胜倾向全部归因于谵妄目标。修复后的样本0（4245805330）初始谵妄目标季、首动召戟且蓝胜，但后续技能与行动次序仍未复现录像。

## 高影响疑点：贝戟被当作护盾实体

千姬召唤物当前shieldEntity=true。通用伤害公式对AOE打护盾实体乘2.5。代码注释明确说helpers.isShieldEntity判据尚未反汇编，只按语义推定。

一个召唤物是否属于这个客户端分类，不能从“有防护作用”直接推出。模型贝戟因此更容易死，失去潮声供火和受击恢复，并迫使千姬重新召戟。修复强制破阵后10场中，7场需要2或3次召戟，4场全场没有潮声返火。

诊断仅取消贝戟的shieldEntity标签，其余保持修复后规则，相同10个种子变为蓝4场全灭获胜、红5场全灭获胜，另1场达到600行动上限后模型判红。说明该未确认分类对战斗结果和长度有较大影响，尚不足以证明2.5倍一定错误。本轮没有修改正式伤害规则，也没有以逼近蓝胜比例为理由调整生命或倍率。

## 尚未确认的额外拉条

模型在召戟后敌方首次技能结束给千姬额外30%行动条，除此之外还有汐梦正常10%。当前核读3562/3563技能行及3561–3569 buff行，未找到该30%的说明；仍可能有隐藏运行时规则，需要进一步取得对应处理逻辑。

诊断取消这一项、保留本轮破阵修复，10场蓝1红9，不能据此判定该机制是否正确。未修改正式规则。召戟成功的样本可能提前让千姬使用汐梦，消耗寻香行所需鬼火，这也是后续顺序与技能分叉的待核点。
