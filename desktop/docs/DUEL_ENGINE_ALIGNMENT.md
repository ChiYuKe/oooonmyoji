# 斗技引擎迁移状态

本轮范围只覆盖用户截图中的十名式神和七种御魂。胜率对比不作为验收方式；规则验证使用状态、事件顺序、固定随机输入和技能等级边界。

## 运行结构

- 运行入口统一使用 `duel/engine` 模块化实现。旧引擎源码、双引擎选择分支和旧引擎回退路径已从斗技运行链路移除。
- 页面阵容格式、`simulateBattle`、`simulateBattleSample` 和 `sampleLog` 继续兼容。尚未迁移的内容走带明确覆盖诊断的通用近似模块。
- 批量场次不再保留整场事件历史，只保留当前请求的样例；事件仍实时结算，并维护最后事件 ID，因此关闭日志不改变战斗状态。
- 截图内容都在独立 `content` 规则模块内，通用结算层不依赖具体式神或御魂 ID。

虫师被动按客户端技能表拆为独立判定：每次攻击至多触发一次，25%免伤与攻击者附加虫之痕分别判定；虫之痕附加继续经过效果命中和抵抗，虫之痕按客户端记录提高30%受伤。新增随机序列回归用例确认免伤失败仍可以附加虫之痕。护盾全吸收等未核定边界仍保持部分覆盖。

蝉冰雪女的蝉翼按客户端状态表设为不可驱散、不可封印，并在自身回合开始时以到期事件移除；到期事件继续触发霜冻清理。正式调度用例验证了到期、不可驱散和霜冻联动。

涅槃之火按本地御魂目录的“行动结束时”触发：生命低于30%时恢复生命上限的15%；被动/御魂封印仍会抑制效果。

结构化战斗日志的单位标签现在从该场最终状态解析，因此召唤物也能按内容提供的显示名记录；海原贝戟不会以内部 unitId 出现在 `sampleLog`。

- `npm run typecheck`：通过。
- `npm run test:duel`：核心与游戏数据对齐专项 269 项通过。
- 当前指定截图阵容的两条定向检查通过：十名式神与七种御魂进入模块化战斗状态，未注册内容数为 0，部分实现项继续通过诊断披露。
