# 内部节点标识约束

节点显示名称与内部 ID 分开。用户编辑 `name`，内部 ID 用于连线、输出引用、运行事件和布局。

- 执行节点使用完整的内置类型名和正整数编号：`root_1`、`task_1`、`sequence_5`、`bool_judge_1`、`simple_parallel_1`。不使用中文、空格、连字符、大写字母、前导零或业务名称。
- 折叠图使用 `node_group_<编号>`；真实边界节点使用 `group_entry_<编号>` 和 `group_exit_<编号>`。
- 同一工作流内节点和折叠图标识唯一；创建、复制、粘贴和旧格式升级共用生成器。自定义节点类型使用其内置基类前缀。
- 编号从 1 起，使用尚未占用的编号。显示名称、位置、动作和节点类型变化都不重新生成已有 ID。
- 旧标识迁移后同步根节点、执行连接、完整输出及字段引用、分支目标、折叠图成员/端点、变量连线、布局、位置锁和连线折点。普通文本、变量键、模板路径与子工作流引用不改写。
- 缺失或重复标识不能确定引用归属，拒绝自动迁移；由现有结构校验报告问题。
- v6 变量数据源节点是格式约定的例外：继续使用 `var__<scope>__<key>`。组内合成接口卡也沿用格式规定的派生标识，不作为执行节点分配编号。
- 工作流 ID、动作名、实例 ID 和变量键属于各自命名空间，本规则仅约束节点及折叠图标识。

权威实现是 `desktop/src/shared/workflow/node-identifiers.ts`。编辑器载入旧工作流时在一次可撤销操作中迁移。

项目文件批量迁移：先在 `desktop` 构建主进程，再运行 `node scripts/normalize-node-ids.cjs` 预检；加 `--write` 执行迁移。脚本先验证反向映射完全恢复原始文档和迁移幂等性，再保存备份与映射表到 `artifacts/node-id-migrations/`。
