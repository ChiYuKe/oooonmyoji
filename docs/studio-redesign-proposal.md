# Onmyoji Studio 界面与架构改造方案

状态：设计提案；未修改现有程序。原型使用示例数据，不执行设备操作。

## 目标与设计原则

日常运行不要求理解节点图；编辑不要求管理窗口；调试能从问题定位到步骤。保留现有 Python 行为树、Action 和 JSON 工作流资产，通过分阶段调整桌面端实现。

视觉采用低饱和中性色、单一蓝色强调、清晰的面板层级。正文 14px，辅助文字 12px，主要操作高度 36px，分组间距 16–24px。支持明暗主题。颜色用于选中、运行、成功和失败，并配合文字表达状态。

## 信息架构

### 运行台

默认启动页。左侧常用任务和设备状态，右侧当前任务参数。任务来自可运行入口，不把公共子流程和开发示例混入日常任务。

标准流程：选择任务 → 选择预设或调整参数 → 分配设备 → 开始。保存过预设后，应允许选中任务直接开始。任务配置应与工作流定义分离；预设记录工作流引用、输入和角色到设备的映射，不复制工作流。

启动前校验参数、工作流、设备连接与占用；失败在对应字段显示原因。设备发现失败与设备为空分别展示。运行中显示已占用设备并阻止冲突启动。

### 流程编辑

顶部仅保留流程名、保存状态、保存、配置运行。左侧流程结构与任务参数，中间画布，右侧所选项属性。素材选择作为属性内的选择器打开；新增节点通过可搜索的添加入口完成，按任务、逻辑、识别、输入和公共流程分类。

常用字段直接显示，失败处理、超时及输出绑定逐步展开。内部 Action 标识放入高级信息。公共子流程支持进入和面包屑返回。

画布、结构树和属性共用同一选中状态。插入节点必须明确父节点与插入位置；孤立节点必须可见并提示。重命名显示名称不改变节点 ID。引用选择展示来源、字段、类型和兼容性。

界面保留拖动停靠和独立窗口，但默认只有一层布局管理。提供编辑、调试预设及恢复默认布局。小窗口折叠结构区，属性以抽屉呈现。

### 运行与调试

按运行记录组织，显示任务、设备、进度、当前步骤和最终结果。步骤详情显示耗时、输入输出摘要、错误原因及关联截图。日志作为补充，不作为唯一状态来源。

“定位节点”打开该次运行对应的工作流与节点；如果当前文档已变化，需要显示版本差异提示。多实例分别显示步骤和结果，停止整个任务与停止单个实例的语义必须区分。

第一期提供查看与定位、协作停止；暂停、单步、从失败处重试不在引擎支持前显示为可用。

## 状态与服务边界

| 模块 | 唯一负责的数据或职责 |
| --- | --- |
| DocumentStore | 按 URI 管理文档内容、修订号、保存修订号、撤销重做 |
| SelectionStore | 当前文档、节点、变量与选择集合 |
| WorkspaceLayout | 面板可见性、尺寸、布局预设；不持有业务文档 |
| TaskPresetService | 入口引用、输入参数和实例角色绑定 |
| RunService | 运行 ID、不可变执行快照、进程状态、取消与结果 |
| AssetService | 素材索引、选择、ROI 和引用关系 |
| Python 引擎 | 编译校验、执行语义、设备访问和结构化事件 |

现有画布和属性 iframe 各持文档并互相替换的方式逐步收敛：先建立宿主文档仓库和有类型的命令协议，再让画布、属性成为同一文档的视图。迁移阶段所有修改携带文档 URI、基础修订号和命令 ID，拒绝过期写入。撤销历史只由文档仓库维护，不在两个 iframe 分别记录。

保存统一走 SaveDocument；运行统一走 StartRun。运行捕获文档修订、输入、设备映射与引用子流程的快照，避免执行过程中读到新修改。保存失败不启动；是否默认保存后运行由明确的产品规则决定，建议首期维持当前保存后运行行为。

TypeScript 与 Python 的语义校验通过共享测试用例保持一致，Python 执行校验作为最终准入。先检查已有契约测试覆盖，再补充缺口，避免同时重写两套规则。

## 运行状态和异常

运行状态：校验中 → 启动中 → 运行中 → 停止中 → 已停止 / 已完成 / 失败。每条事件携带 runId、instanceId、workflowId、nodeId、序号及时间。旧运行的迟到事件不得覆盖新运行。

停止优先请求协作取消并等待终态，超时后提供强制终止；不把“停止请求已发出”当成“已停止”。设备锁以实际资源释放为准。独立任务并行需要 RunService 从单进程字段升级为运行集合，并验证设备冲突；第一期不承诺该能力。

关闭或切换未保存文档提供保存、丢弃、取消。默认工作流关闭设置必须覆盖所有启动路径。空任务库提供选择入口，设备离线提供刷新与诊断，校验错误提供字段或节点定位。

## 落地顺序与验收

1. 编辑器整理：精简工具栏、属性分组、单层默认布局、统一视觉。验证常用节点可通过一个入口找到，选中节点与属性一致，布局可恢复。
2. 文档状态整理：统一保存、撤销、导航与修订。验证画布和属性交替修改后的撤销顺序；连续切换文档不串写；保存失败保留修改。
3. 运行台与预设：复用入口和现有执行接口。验证参数持久化、角色绑定、校验定位和重复启动保护。组队与单人两种场景均可从运行台完成。
4. 调试整合：运行记录、结构化步骤、截图关联与节点定位；接入协作取消。验证取消超时、进程启动失败、多实例部分失败、旧事件隔离。
5. 高级能力：设备互斥前提下独立任务并行、布局预设持久化、更多编辑快捷操作。根据前四阶段反馈确定优先级。

## 原型范围

可切换三个工作区，选择任务与预设、验证实例分配、演示开始和停止、选择并修改节点、添加等待步骤、从记录定位节点。修改只保存在预览内存中。流程图是交互示意，未连接 JSON 编辑器；设备、耗时和进度均为示例。正式接入需要遵守上述状态、引用和执行规则。
